## 2. 端到端渲染验证（烧卡，逐项人工审）

### E1 · JSON 白膜 → H3 成片（核心对照实验）
- **目的**：验证「AI 填表 → 机器渲染 → H3 成片」全链替代手 K 白膜。
- **步骤**：`cli/whitebox.mjs render lab/whitebox/fight.unit.json` → `cli/utility.mjs workflows/h3-fun-whitebox.json --video <产出的 fight.mp4> --set 172.strength=1.0`，**seed 固定 `20260928001`**。
- **判据**：与 09-28 手 K 版成片（`lab/h3-whitebox/out/s100/`）对照 —— 构图/位移/时序逐格对应；身份锁（陈默/林晓）；灰色不渗；音轨有内容。
- **成本**：渲染 ~40s + H3 ~266s。
- **已知差异预期**：UAL 出拳节奏 vs 手 K 蓄力分解不同，属表演层差异，不算失败；空间/时序错位才算。

### E2 · jet 场景（刚体链路试金石）
- **目的**：一次验证 prop 刚体轨迹 + valley 地形 + 相机模板 + 多目标时序。
- **前置**：手写 `lab/whitebox/jet.unit.json`（jet + 2~3 枚 missile 交错 + valley + pan-follow 跟拍）。
- **判据**：白膜静帧 —— 导弹数量对、交错时序对、飞机不出山谷；H3 成片 —— 导弹不丢（480p 小目标风险点，丢了按 schema「导演式作弊」节放大/拉近再试）。
- **成本**：白膜 ~1 min + H3 ~5 min。

### E3 · strength 档位对照（0.75 / 0.5）
- **目的**：补 09-28 欠的单变量对照，量化「构图保真 ↔ 画面自由度」。
- **步骤**：同一 fight.mp4、同 seed `20260928001`，只改 `--set 172.strength`。
- **判据**：走位/朝向是否开始漂移；哪档开始丢构图。
- **成本**：每档 ~4.5 min。

### E4 · start/end_percent 窗口（备选旋钮）
- **目的**：验证「前 60% 步数钉构图、后 40% 松手收敛」是否优于整体降 strength。
- **步骤**：`--set 172.end_percent=0.6`，其余同 E3。
- **判据**：构图保持 + 末段质感是否更自然。
- **成本**：~4.5 min。E3/E4 合计三轮，一次坐下来跑完。

### E5 · 真实参考视频通道（三通道判据的第三通道）
- **目的**：验证菜单外特技（托马斯/后空翻类）走真实视频 control_video 是否成立。
- **前置**：一段 3-5 秒真实特技参考视频（用户供或素材站）。
- **判据**：H3 跟得上动作 → 第三通道成立写进 schema 适用范围的实证；跟不上 → 结论改为「此类动作现阶段剧本层面避开」。
- **成本**：~5 min（不用改工作流，control_video 不挑输入）。

### E1 结果（09-29，seed 20260928001 / strength 1.0 / 168 帧输入单变量）

- 白膜渲染 46s（168 帧），H3 生成 5m48s，产物 `MiniMax_H3_00008_.mp4`（480×864 / 175 帧 / 7.29s / AAC 32k stereo / mean −24.9 dB）。
- **逐格对照通过**：二人推进 → 对峙 → 受击下跌（f144 左右）→ 一人倒地一人站立，
  与白膜同一时间点的姿态与画面位置对应；身份锁住（陈默深灰上衣黑裤 / 林晓米白阔腿）；灰色未渗入成片。
- 与手 K 版基准（`s100/`）的差异：构图/位移/时序一致；表演层是 UAL 动作风格（非手 K 蓄力分解），
  属预期差异，不算失败。
- K1 已在 E1 产物上完成，详见 `lab/spatial/FINDINGS.md`。

### E2 结果（09-29，固定侧向广角机位）

- Blender 输出 168 帧 PNG，ffmpeg 封装为 480×864 / 24 fps / 7 秒 `jet_valley.mp4`。
- 飞机与三枚导弹均在关键帧中可见，主体在框率均为 100%，屏幕位移分别为 `0.52 / 0.33 / 0.32 / 0.25`；F1/F2/F3/D1 取景预检通过。
- 原先的 `pan-follow` 会把飞机的屏幕位移压成 `0.00`，因此改为固定机位以保留运动可读性。该结论适用于需要观察屏幕运动方向的白膜镜头；跟拍镜头仍应单独设计取景约束。
- H3 成片已完成；白膜取景与生成模型保持能力分开记录，避免把两类问题混成一个通过结论。

### E2 H3 结果（09-29，seed 20260929002）

- 刚体专用工作流 `workflows/h3-fun-jet.json` 去除了人物参考图，只保留白膜控制视频和刚体场景提示词。
- H3 生成 175 帧 / 7.29 秒，带 AAC 音轨；抽帧网格显示飞机、三枚彩色导弹和山谷背景连续可读，导弹按红 → 黄 → 橙顺序出现并沿山谷方向运动。
- 通过的是“运动语义与身份颜色保持”检查，不把它当成精确坐标通过：生成结果的飞机屏幕位置会被模型重新构图。下一步应把 H3 首、中、末帧重新送入 `measure-whitebox`，记录与 `coords.json` 的偏差，再决定是否提高 control strength 或改用关键帧约束。
