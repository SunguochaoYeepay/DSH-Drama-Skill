# 白膜道具资产库

白膜道具是可复用的空间基准，不是每个剧本临时生成的装饰。处理白膜规划时，先按 `asset_id` 查本地库；本地没有，再从允许使用的来源获取；只有没有合适模型时才生成基础几何或新模型。

## 资源优先级

1. `vendor/whitebox-assets/props/` 中已有并通过元数据校验的模型。
2. 已批准的外部资源来源。下载前确认许可证允许项目用途，并把来源、作者、许可证和原始 URL 写入资源清单。
3. 本项目生成的新模型。保存源文件和导出文件，不能只保存渲染结果。
4. 基础几何体兜底。必须标记为 `procedural_fallback`，不能冒充正式资产。

不要把带过期签名的下载 URL 写入剧本、空间计划或白膜 JSON；模型必须落到本地稳定路径后再被引用。

## 入库要求

每个道具至少需要：

- 稳定的 `asset_id` 和模型文件（优先 `.glb`，保留源 `.blend` 或原始下载文件）。
- `kind: prop`、`asset_type`、真实尺寸、原点约定和朝向约定。
- 碰撞包围盒或简化碰撞体，供轨迹和穿插检查使用。
- 可交互锚点；椅子至少声明 `seat` 锚点和座面高度，桌子至少声明桌面高度。
- `license`、`source_url`、`author`、`retrieved_at` 和内容哈希。
- 一张仅用于人工核对的预览图。

导入 Blender 后统一单位为米，脚底或物体接触地面为 `z=0`，局部前方统一为 `+Y`。模型文件不得带不可见的大尺度偏移、隐藏动画或会覆盖白膜根节点的根运动。

## 坐下场景

“三个人坐在方桌前”需要桌子、三把椅子和三个人的座位锚点。空间计划应引用桌椅 `asset_id`，人物先走到对应 `seat` 锚点，再按动作库使用：

- `Sitting_Enter`
- `Sitting_Idle_Loop` 或 `Sitting_Talking_Loop`
- `Sitting_Exit`

座位朝向由椅子锚点或计划显式指定，不能靠镜头方向猜。桌椅的模型外形可以简单，但其尺寸、座面和碰撞关系必须稳定。

## 生成或下载后的检查

入库前检查：

1. 能在 Blender 中打开并只显示预期几何。
2. 尺寸、原点、朝向和接触面符合元数据。
3. 不穿地、不漂浮，碰撞包围盒与模型大致一致。
4. 许可证和来源字段完整，内容哈希稳定。
5. 用一个最小白膜场景渲染静帧，人工确认轮廓可读。

入库后，白膜 JSON 只引用 `asset_id`，不把远程地址、临时文件名或生成提示词当作资产身份。

## 与现有工程的衔接

- 人物继续使用 `vendor/whitebox-assets/manifest.json` 中的 UAL 资源和动作。
- 道具清单放在 `vendor/whitebox-assets/props/manifest.json`，白膜 schema 只允许清单中的道具类型。
- 白膜渲染器只负责加载清单资产和应用 Stage 位姿；找不到资产时应明确报错或显示 `procedural_fallback`，不能静默换成别的模型。
- 资源阶段需要新增道具时，先更新资源库和清单，再写空间计划。
