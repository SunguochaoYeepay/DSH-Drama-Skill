# 空间核查（space-check）

> **一句话**：这套东西**不控制画面**，它把"空间对不对"从"靠记忆和感觉"变成**一张带自动数据和待确认项的核查单**。
> 控制类的三条路（线框示意图 / 真实照片+人形标记 / 提示词强制声明）都在 `lab/spatial/FINDINGS.md` 里被实验证伪了，别再走。

## 什么时候用

**出完关键帧、签署之前。** 尤其是这几类镜头：

- 两人以上同框，或对谈（正反打、过肩、视线）
- 机位换边（同一场从另一个方向拍）
- 有人**没进画**、或人数可能不对
- 这一镜**没有落幅**（会静默走 i2v，构图不受端帧约束）

## 三条命令

```bash
# ① 主体存在性 / 人数：画里有没有人、几个人（检出没人 → 退出码 1，可当闸门）
node cli/check-subjects.mjs <项目目录>

# ② 空间核查单：声明 → 自动结论 → 待人工确认；同时写 reviews/space-check.md
node cli/space-check.mjs <项目目录>

# ③ 出片时的静默失败提示已经内置（cli/unit.mjs / cli/keyframes.mjs 会自动打印）：
#    · 缺落幅 → 本镜走 i2v，构图不受端帧约束
#    · 声明的道具其实没进参考图（本地/百炼/火山通道只下发 场景 + 身份）
```

## 声明写在哪：`space.json`（旁挂，不进票据）

**不要写进 `board.json` / `render.plan.json`** —— 那两个是哈希绑定的票据产物，塞进去会让别人已有的确认全部失效。
空间声明是**可选的、增量的**，就该长在票据之外。

```jsonc
{
  "axis": { "a": "她这侧", "b": "他那侧" },
  "units": {
    "g001": {
      "camera_side": "B",                      // A | B | on-axis
      "subjects": [                            // 单元级（粗略）：谁在哪、朝哪、前后
        { "id": "gu_xing_dinner", "at": "他席位", "facing": "away", "depth": "near" }
      ],
      "shots": [                               // 逐内部镜头（单元内有切镜时**必须**写到这一层）
        { "n": 2, "camera_side": "B", "subjects": [{ "id": "su_wan_dinner", "facing": "toward_lens" }],
          "observed": { "su_wan_dinner": "toward_lens" },   // 人看着画面记录到的**实际**方向
          "note": "她抬眼笑、开口；他在镜头这一侧，所以朝镜头就是朝他" }
      ],
      "relations": ["过肩：他在画面右侧近处、背对镜头只露后脑与右肩"],
      "human_review": "右侧近处是否是他的背影（不是第二个正脸）",
      "verified": { "by": "人", "result": "pass", "note": "已核对：…" }
    }
  }
}
```

方向取值：`screen_left` / `screen_right` / `toward_lens`（朝镜头＝朝镜头那一侧的那个人）/ `away` / `down` / `front`。

## 机器判什么、人判什么（这条最重要）

| | 谁判 | 说明 |
|---|---|---|
| 画里有没有人、几个人 | **机器** | 本地检测器，在 32 张真实成片关键帧上 100% 可用 |
| 轴：同一主体的**视线方向**在相邻镜之间翻转 | **机器** | 纯逻辑。这才是越轴的症状 |
| 机位换边（A↔B） | **机器，但只报 ℹ** | 过肩正反打**合法地**跨两侧拍 —— 一律当越轴是错的（这里踩过坑） |
| 逐内部镜头的视线一致性：两人都朝同一屏方向 且 两镜机位同侧 → 没在看对方 | **机器** | 纯逻辑。方向由人记录（`observed`），机器只查一致性 |
| **两人是否真的在相向 / 桌子在不在两人之间 / 朝向是否相交** | **人** | 分割、骨架、多模态模型**全都不可靠**（会给出"自信的错答案"）。机器只把它们**列成待确认**，不假装判过 |

分工一句话：**人看方向，机器查一致性。** 别让机器去判方向。

## 两条已验证的经验（都是真事）

1. **抽象关系句会翻车**：「两人隔着餐桌面对面坐」+ 三条"绝不并排"的强否定词 → 出来的是**并排同侧、各看各的盘** ✗。
   **换成可见的遮挡结构就成立**：「竖幅双人过肩中景，机位从他的席位斜后方越过他的右肩推向对面；画面右侧近处是他的侧后背影，占约 1/3；主体是左前方隔着餐桌正对镜头的她」✓
   —— 因为**"有人背身进前景"这个结构本身就排除了"并排同侧"**。
   顺带结论：**"两人面对面"在影视语言里本来就不靠一张正对的双人镜实现**，靠正反打/过肩配对 + 视线守恒。

2. **落幅是唯一的"控制"**：`keyframe-prompts/<单元>.last.txt` 直写落幅 → 出片走 fl2v（首帧+落幅）。
   实测：落点波动 0.089 → 0.001；复杂运镜相邻帧差中位 19–23 → 2.8–3.7、背景漂移 p90 79.5–94.5 → 28.5–29。
   没有落幅的镜头会**静默**走 i2v（模型可自行改机位）——`cli/unit.mjs` 现在会把它说出来。

## 边界（别当它是控制器）

- 它**不能**让模型画出它画不出的构图。它能：**发现**画错、**钉住一镜两端**（落幅）、**换成结构上成立的拍法**。
- 一个单元里有多个内部切镜时，落幅只钉得住**最后那一帧**；中间怎么走管不了。
- 声明与提示词可能**两张皮**（提示词的几何 vs `space.json` 的声明）——两者不一致时，核查单按声明判，可能给出"符合"的假象。**写声明时要对着提示词核一遍。**
