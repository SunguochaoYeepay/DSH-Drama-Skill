# 抽卡师

抽卡师是导演和生图模型之间的执行编译层。它不创作剧情，也不拥有台词、角色设定、场景语义或单元边界；它只把导演已经决定的镜头意图翻译成当前生图模型可执行、可检查的语言。

## 输入与输出

输入包括导演单元、关键帧起始姿态、景别、机位、出镜角色、参考图职责和项目级执行覆盖。输出至少包含：

- 原始意图（不得丢失）。
- 人物身份、场景、姿态和空间几何约束。
- 参考图职责和模型语言。
- 冲突列表；不能满足的约束要报告，不得静默随机妥协。
- 最终生图提示词和必要的执行层补充。

时间轴词必须翻译成静态画面词：例如“0秒时女孩仰面躺着”应变成“关键帧起始姿态：女孩仰面躺着”，不能把视频时间直接喂给生图模型。

抽卡师可以把“躺着”“站在床边”等软动作展开成可验证的几何关系，但不得擅自改变动作。若“近景”无法证明“沿床长边躺下”，必须报告景别冲突，由导演或人工决定是否改成中景；抽卡师不能静默改景别。

抽卡师的结果要随生成记录留痕。生成失败或人工不满意时，先判断是编译冲突、提示词缺陷还是抽卡波动，再决定修覆盖或重抽。

## 非人类卡司：取景与承托必须重新推导

> 🔁 **已复发（最近：bike_stare 2026-09-19）**：同一串「承托物、**床头/床尾**、道具和镜面关系」又原样进了两条关键帧提示词（主体分别是站在草地小径上的女生、和骑车的男生 —— **两者都与床无关**）。
> 机器计数：提示词落盘产物里能查到的**至少 3 次关键帧生成、跨 2 个剧目**（`mimi_bone` 1 次 + `bike_stare` 2 次；结果文件每次重跑会被覆盖，所以这是**下限**）。
> 到 2026-09-19 为止，下面那张表列的四处措辞**一处都还没改** —— 记了却没拦住，这正是「复发」的定义。

执行层现成的取景规则是**按人类、且按床上场景**写的。套到四足动物身上会同时注入多条互相无关甚至冲突的约束。已在 `mimi_bone`（2026-09-19，一条趴在客厅地板上的柴犬）实测到四处：

| 现成措辞（代码位置） | 对四足动物为什么不成立 |
|---|---|
| 「中景：画面下边界严格切在**人物的腰部**（腰带/腰线位置）」（`cli/keyframes.mjs` 的景别规则） | 狗没有腰带/腰线；趴姿的中段不是腰 |
| 「承托物、**床头/床尾**、道具和镜面关系」（`cli/keyframes.mjs` 的空间关系） | 客厅地板上的动物没有床头床尾 |
| 「不应出现**鞋子、拖鞋或站立姿态**；不要把身份图中的鞋履和站立姿势复制到**床上躺卧**镜头」（`src/draw-specialist.mjs` 的当前镜头排除） | 没有鞋子，也不在床上 |
| 「严格保持**此人**的脸、发型和服装」（`cli/keyframes.mjs` 的参考图职责） | 不是人 |

**规则**：`characters[].species ≠ human` 时，抽卡师不得让上述人类专用约束原样进提示词，必须换成物种感知的等价物 —— 承托面、四肢落点、身体轴线朝向、头身相对位置。冲突按本文件既有要求**报告**，不得静默随机妥协。

**注意这一条的性质**：成图可能"看起来还行"，但那是模型自己扛住了矛盾，不是契约成立。`mimi_bone` 的关键帧确实出了可用的图，同时也确实带着这四条矛盾 —— 两者可以同时为真，不能拿"图能用"当作"约束没冲突"。

**已有先例**：`cli/keyframes.mjs` 里已经为「老鼠与猫」写过物种专属的体型比例硬约束，说明工程承认需要按物种处理；缺的是把景别与承托这套**通用**规则也补上物种分支。

> **2026-09-20 修复进展**：表中「承托物、床头/床尾、道具和镜面关系」那句**已在 `cli/keyframes.mjs` 改成通用措辞**；覆盖路径那段硬编码的床戏截取范围也已修掉（覆盖文本本身即画面截取范围，并带一条回归测试：覆盖文本里没有的东西，提示词里不许出现）。**表中另外两处仍未改**：景别规则的「切在人物的腰部」、`src/draw-specialist.mjs` 的「鞋子/拖鞋/站立姿态」排除项。

## 多主体同框时，造型描述没有点名归属

执行层把本单元 `on_screen` 的造型描述**按顺序拼成一段**塞进提示词，**没有写明哪一套属于谁**。
`pot_hit`（2026-09-20）实测：两个老头同框，一个该穿浅灰汗衫、另一个该穿深墨绿外套并戴老花镜；
提示词里两套描述并列出现，模型无从分配，结果**把两个人画成了同一张脸、同一件灰汗衫**。

**处置（这条已经可以用覆盖兜住）**：用项目级覆盖 `reviews/keyframe-overrides.json` **逐人点名**：

```jsonc
{ "units": { "g002": "构图覆盖：中景。画面右侧坐着的是大爷：方圆脸、花白短发、不戴眼镜，穿浅灰色短袖汗衫……；画面左侧坐着的是棋友：瘦长脸、灰白长发、戴细金属框老花镜，穿深墨绿色薄外套……两名老人必须长相不同、穿着不同。" } }
```

实测一次到位，两个老人当场变得可辨。**执行层的编译本身还没有做归属**，所以只要两个以上主体同框、且他们的造型需要区分，就应当写覆盖点名。
