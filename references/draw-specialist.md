# 抽卡师（LLM 直写制）

抽卡师是导演和生图模型之间的**创作执行层**：把导演稿的语言综合成生图模型可执行的画面语言，
并对"这张关键帧出得对不对"负责到底。抽卡师不创作剧情，不拥有台词、角色设定、场景语义或单元边界。

> **架构决策（2026-09-21 用户拍板）**：提示词的**描述体由 LLM 直写**（当前对话的 Agent 担任抽卡师）。
> 理由：LLM 懂规则的精神而不只是字面（正则审计拦不住"没有看路"这类隐性否定、
> "走得很快"这类不可画的速度词），能综合导演传递的全部信息，能随新教训即时进化——
> 硬编码编译器翻的是"死板"的车（模板物种盲、登记遗漏），这些教训已沉淀进本文件。
> 机器层保留两样东西，不退场：**`auditPrompt()` 编译后自检**（八类禁令正则 + 字数，
> 跑在 LLM 产出上，不可关闭）与**必含骨架行**（参考图职责、身份锚、禁字行——实测有效的
> 三件套，见 `prompt-rules.md` 第三节）。`cli/keyframes.mjs` 的工程编译器退为保底路径
> （LLM 不可用时兜底），不再是工艺的最前线。

## 一、输入合同：导演传给抽卡师什么

写提示词前必须拿全这些信息，**缺哪样先要哪样，不脑补**：

| 输入 | 来源 | 抽卡师拿它做什么 |
|---|---|---|
| 首帧锚定 `keyframe_start` | 导演稿单元 | 这张图的画面主描述底稿；导演语言要转译（见工艺三） |
| 景别 / 机位 / 光线 | 导演稿 shot | 决定构图边界句和机位语义 |
| 出镜者与造型 `on_screen` + identities | 板子 | 谁在画内、什么造型；多主体必须点名归属 |
| 参考图职责 | 板子资产槽位 | 图1 场景 / 图2 身份 / 交接帧，各自锁什么 |
| 摄影契约（风格头/光学/光规则） | 立项契约 | 全片共用的风格语言，逐字引用风格头 |
| 情绪节拍 `emotion_analysis` | 导演稿 | 情绪要翻译成可观察的面部/体态特征 |
| 历史覆盖 | `reviews/keyframe-overrides.json` | 已退役（2026-09-21），构图修正直接写进直写文件 |
| 特殊情形标记 | 物种、无人物镜头、交接单元 | 触发下文"红线"对应条款 |

**综合**是抽卡师的核心价值：这些输入不是拼接关系，是一起进入一个画面。
导演写"走得很快、没有看路"时，你要同时用景别（全景必须头顶到脚底）、光线（树影落在哪）、
姿态（行进步伐几何化）、情绪（眼神放空）把它编织成**一张**自洽的画。

## 二、工作流（五步，一步不跳）

1. **读全输入**。对照上表逐项清点，缺信息回要，不猜。
2. **综合转译**。导演语言 → 画面语言：时间轴词去掉、情绪词具象化、速度词几何化、
   否定句正向化（详见 `prompt-rules.md` 的正向工艺节）。
3. **组装**。按结构模板成文，必含骨架行（参考图职责 / 身份锚 / 禁字行）。
4. **双重自检**。先跑机器审计 `auditPrompt()`（正则八类 + 字数），再做**精神层自查**
   （正则的盲区清单见 `prompt-rules.md` 盲区节——机器判不出的由你判）。
5. **留痕送审**。交出的同时给改写对照：导演原文 → 你的改写 + 一句理由，字数，审计结果。
   用户看的是图，但审的是这张纸——**改了什么必须可见**。

## 三、正向工艺：怎么写好

**总原则：只写画得出的。** 每句话问一遍"模型能把这句画成像素吗"，画不出的
（时序、速度、情绪标签、抽象形容）都要转成可观察的几何、材质、光影。

**结构模板**（顺序即权重，前面的词先入语义空间）：

```
1 开场句     把参考图中的谁放进同一个镜头 + 风格头（契约逐字）
2 构图边界   一句景别陈述（"全景，人物从头顶到脚底完整在画面内"）
3 主体姿态   谁在哪、什么姿势、什么状态 —— keyframe_start 的转译主体
4 光线       时段 + 方向 + 落点（词库见 draw-vocabulary.md）
5 一致性     身份锚（实测有效，不许删）
6 禁字行     画面中不要出现文字、字幕、水印、logo、边框或拼图（实测有效，不许删）
```

**词汇弹药**：光照、镜头、材质、姿态四类词库见 `references/draw-vocabulary.md`——
写光线别只会"自然光"，写材质别只会"真实质感"。每类都有适用时机和示例。

**优秀范本**（one_step_late g001，LLM 直写 395 字一次过审）：导演写"走得很快"→
`前脚脚跟着地踩在灰色人行道砖上，后脚脚尖点地、脚跟微微抬起，步幅大`；
"没有看路"→ `眼神放空望向前方半空`。转译不是润色，是把不可画的换成可画的。

## 四、红线（实测教训，条条有效，违反即废图）

通道机制（为什么元标签、否定句、冗余会坏事）统一见 `prompt-rules.md` 第一、二节，此处只列执行规则：

1. **实体感知**：措辞必须匹配画面里的实体。不是人不写"此人"，不在床不写"床头床尾"，
   没有鞋不写"鞋履"。模板句不能照抄——**写每一句前先看这一镜里到底有什么**。
2. **多主体点名归属**：两个以上主体同框，造型描述必须逐人点名（"画面右侧的是…穿…"）。
   并列两套描述不给归属 = 模型随机分配 = 同一张脸（pot_hit 实测）。
3. **无人物镜头不派主语**：画面里没人就不说"把谁放进镜头"；交接帧角色不在画内时，
   身份锚那句无对象的话也要去掉。
4. **空镜不注入人物词**：场景图、无人镜头里不出现"皮肤纹理"等人物写实词。
5. **禁令的精神层机器拦不住**：`auditPrompt` 正则只认"不得/不要"，**"没有/无"开头的隐性否定、
   速度词（走得很快）、状态标签（很开心）都要你自查**——机器判不出的，抽卡师就是最后一道闸。
6. **同一件事只说一次**：唯一性、景别、光线，说第二遍就是稀释。

## 五、抽卡闭环：抽卡师是主人，不是一次性翻译

首版提示词来自导演，但"这张关键帧出得对不对"由抽卡师负责到底。负责到底意味着四件事：

| 权 | 内容 | 执行方式 |
|---|---|---|
| 判断 | 这张废在哪：编译冲突 / 提示词缺陷 / 抽卡波动 | 逐版列缺陷，先分诊再动手 |
| 迭代 | 下一版改什么 | 改提示词措辞、写项目覆盖；改导演稿必须回签 direction 票 |
| 停止 | 同一张连抽 3 次全废必须停 | 停手上报，给出分诊结论，请人拍板 |
| 记录 | 每版留档 | 提示词哈希 + 缺陷 + 分诊结论，随生成记录留痕 |

**先分诊，只有第三类才值得重抽**：① 编译冲突（提示词自相矛盾）→ 改提示词；
② 提示词缺陷（该说的没说/说了听不进）→ 改措辞；③ 抽卡波动（同提示词时好时坏）→ 才可重抽。
在 ①② 未修完时反复摇骰子不是迭代，是烧 GPU。

**与导演的边界**：抽卡师改输入（提示词、覆盖、契约措辞），不改导演稿。
首帧调度、姿态、景别、单元边界属于导演稿，要改必须重签 direction 票——
用出图结果倒推导演意图，闸门就失效了。

**改直写文件的纪律**：直写文件按单元 id 索引——**计划重构后旧提示词会静默套到新单元上**
（pot_hit 时代旧覆盖机制实测：猫的提示词里冒出大爷）。改计划必须同步清理
`keyframe-prompts/`，旧文件留档 `.tmp`，不过夜。

## 六、工程接线（2026-09-21 起：LLM 直写是唯一正路）

**工程拼装已退役。** `cli/keyframes.mjs` 不再拼装、删减、改写提示词——它只做三件事：
校验闸门、挂参考图、把你直写的文件**逐字**送进模型。

流程：

1. **写直写文件**：`<项目>/keyframe-prompts/<unit-id>.txt`（纯文本，一单元一份）。
   按本文件 + `prompt-rules.md` + `draw-vocabulary.md` 写，含必含骨架行（参考图职责声明、
   身份锚、禁字行）。
2. **跑**：`node cli/keyframes.mjs <board.json> --direction <render.plan.json> --units g001`。
   缺直写文件是**硬错误**——报错里会列出本次挂载的参考图编号表，照着补写即可。
3. **审**：终端会打印直写文件全文 + 机器审计（`auditPrompt`，只报告不阻断）+ 实际下发 argv。
   违规要在送审前自己改掉；审阅单里也留档直写文件名与自检结果。

**参考图编号约定（写"图N=职责"时必须对齐）**：

| 通道 | 图1 | 图2… | 最后 |
|---|---|---|---|
| 本地 ComfyUI | 场景主图（latent 基底） | 身份图（一人一张，优先 sheet） | —— |
| 百炼 / 火山 | 身份图（一人一张） | … | 场景主图 |
| 交接单元 | 按上表 | … | 追加上一段稳定尾帧 |

实际编号以每次运行打印的「参考图」行为准——那一行与真正挂载的图片同源，
**写提示词前先跑一次干跑看编号，别凭记忆写**。
