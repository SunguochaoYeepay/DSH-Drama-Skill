# 摄影语言契约

立项、生成关键帧或生成视频时读取本文件。它定义**用什么机器拍**，不定义**画成什么样**。

## 为什么单独一层

`board.meta.style_prompt` 回答的是美术风格：古风仙侠、写实、3D 卡通。
它回答不了这些：多长的镜头拍、景深多浅、机位在多高、主光从哪边来、光比多大。

这两件事混在一起的后果是：**每一帧的脸型透视和光的方向都由模型随机选。**
同一部剧里，前一镜是 85mm 压缩感的大脸，后一镜变成 24mm 的广角变形，观众说不出哪里怪，但就是不像一部戏。

对标 `0xadvait/ai-video-pipeline` 和 `Adityaraj0421/ai-cinematic-video-director-claude-skill` 之后，
这是差距最确定的一项 —— 它们有焦段、有光位、有逐字风格头，我们原来一个都没有。

## 文件位置与时机

项目目录下的 `cinematography.json`，与 `board.json` 同级。**立项时定，人工确认一次，全片共用。**

它和风格、画幅一样属于立项必问项。用户没有提供时**必须问**，不能由 Agent 静默填一套。

> ⚠ **改了契约 = 全片换机器：受影响的产物必须全部重跑、重新送审、重新批票。**
> 契约是资产 / 关键帧 / 视频三类提示词的**输入**，但票据绑的是产物文件哈希、**不绑契约** ——
> 改完契约不重跑，旧票依然"全绿"，`ready-assemble` 照常放行，前后两种风格缝进同一部成片，
> 要到终审用眼睛才看得见。改之前想清楚：你是要换全片，还是只修一镜？
> **只想改一镜的光 / 焦段，不要动契约** —— 用导演稿的 `shot.optics` / `shot.lighting_setup`
> 每镜覆盖，只重跑那一个单元；契约动的是全片，覆盖动的是单镜。

## 三条硬规则

**1. 契约里没写的字段，一个字都不输出。**

代码不会替你补一个"50mm 应该差不多"。宁可提示词里没有这一层，也不能让机器替导演编。
这是 SKILL.md「不能由 Agent 静默猜默认值」的直接延伸。

**2. `style_header` 逐字进提示词，且永远在最前面。**

它是全片所有视觉提示词的公共前缀，作用是压住模型往插画 / 水彩 / 日系动画方向漂。
改写过的前缀等于没有前缀 —— 每帧措辞不一样，模型就会当成"这次是个别的"。

**3. 每镜覆盖优先于契约。**

导演在 `shot.optics` / `shot.lighting_setup` 里写了就听导演的；没写就继承项目契约。

## 字段

```jsonc
{
  "version": 1,

  // 锁定风格头 —— 逐字进所有视觉提示词的最前面
  "style_header": "电影级写实摄影，青绿与暖阳金主色调，清透林间光效，细腻皮肤质感",

  // 风格排除。写"不要什么"，不是写"要什么"
  "negatives": ["线稿", "水彩", "日系动画", "厚涂插画", "过曝高光"],

  // 焦段。可以是数字（全片一个），也可以按景别给表
  "lens_mm": { "default": 35, "远景": 24, "全景": 35, "中景": 50, "近景": 85, "特写": 85 },
  "depth_of_field": "浅景深，背景柔化分离",
  "camera_height": "视线高度",

  "lighting": {
    "key_direction": "左上方 45 度",   // 主光方向
    "quality": "柔和散射",              // 光质：硬光 / 柔和散射 / 直射
    "ratio": "低反差，暗部保留细节",     // 光比
    "temperature": "暖调 3200K",        // 色温
    "fill": "",                          // 补光，可选
    "rim": "侧逆光勾出发丝边缘",         // 轮廓光，可选
    "practicals": ""                     // 环境光源，可选
  }
}
```

所有字段都是**可选**的。缺哪一项，提示词里就没有哪一项，不会报错也不会兜底。

### 焦段怎么选

焦段决定透视变形，是"脸像不像同一个人"的最大变量：

| 焦段 | 效果 | 常用景别 |
|---|---|---|
| 24mm | 广角，边缘拉伸，空间夸张 | 远景 |
| 35mm | 接近人眼，环境与人并重 | 全景 |
| 50mm | 标准，几乎无变形 | 中景 |
| 85mm | 压缩背景，脸型讨喜 | 近景、特写 |

上表是**选段参考，不是默认值**。抄进契约之前必须人工确认它符合这部剧的观感。

### 光的字段为什么拆这么细

`shot.lighting` 是文学描述（"晨光斜射穿过枝叶，空气通透"），它表达氛围，但不构成可执行的约束 ——
模型每次对"斜射"的理解都不一样。`lighting_setup` 是技术参数，每次都一样。

两者**同时进提示词**：技术参数在前保证一致性，文学描述在后保留导演的氛围意图。

## 全片物理规则与覆盖

对标 `0xadvait/ai-video-pipeline` 的 `CRITICAL SHADOW RULE`。

精髓不是"写了一条影子规则"，而是**规则全局生效 + 单镜可翻转**：影子全片都投向主光反方向，
唯独某一镜要逆光，就在那一镜写覆盖。没有覆盖语法的话，要么规则不敢写死（每帧各自发挥），
要么写了死规则后被一个特殊情况逼着去改全片契约。

```jsonc
{
  "rules": [
    { "id": "shadow", "text": "所有影子必须投向主光的反方向，方向与长度全片一致" },
    { "id": "scale",  "text": "老鼠站立身高不得超过猫的五分之一，且必须位于猫脚边" }
  ]
}
```

每镜覆盖，写在导演稿的 `shot.rule_overrides`：

```jsonc
{
  "rule_overrides": {
    "shadow": "本镜例外：人物背光站立，影子投向镜头方向",
    "scale": ""            // ← 空串 = 本镜不适用这条
  }
}
```

四条规矩：

1. **规则必须有 `id`。** 没有 id 的规则不能被覆盖，也就不算"可被翻转的规则"，会被跳过。
2. **空字符串 = 本镜不适用**，不是"沿用原文"。和「契约里没写的字段不输出」同一条纪律。
3. **覆盖只影响本镜**，其余镜照旧拿契约原文。
4. **规则不进资产。** 参考板与空镜没有卡司，"老鼠不得超过猫的五分之一"写进空镜提示词，
   等于给模型递了一份"要画什么"的词表 —— `masterPrompt` 里那只腾空跳起的橘猫就是这么来的。

规则是**每镜带的**（跟镜头、光一样），不是全片前缀一次。因为不同镜的覆盖不同，
一次前缀无法表达。全片前缀只有风格头和风格排除。

⚠ 物种专属的体型硬约束（`cli/keyframes.mjs` 里猫鼠那条）是**代码拥有**的，
与契约规则并存、不相干 —— 那条不靠人写，也不该被覆盖掉。

## 资产吃哪几层

契约不只作用于关键帧和视频，**资产也吃**，但**不是全套**。判据只有一条：**这张图是"锚"还是"画面"。**

| 资产 | 风格头 | 排除项 | 焦段 | 光 | 判据 |
|---|---|---|---|---|---|
| `portrait` 肖像 | ✗ | ✓ | ✓ | ✗ | 锚。色调与光一旦进去，全片基调就被锁死在一张脸上，换场就不对。但媒介必须锁（画成插画脸＝整片废）、焦段必须锁（24mm 拍脸和 85mm 拍脸不是一个人） |
| `sheet` 身份图 | ✗ | ✓ | ✓ | ✗ | 同上，它是肖像的延伸锚点 |
| `master` 场景主图 | ✓ | ✓ | ✓ | ✓ | **画面**。这才是全片的风格锚与光锚 —— 它喂给全部关键帧，它长什么样全片就长什么样 |
| `prop_3view` 道具 | ✗ | ✗ | ✗ | ✗ | 自带"写实产品静物摄影"配方。把卡通片的全片风格头套到手机、镜子上是错的 |
| `reverse_master` / `spatial_layout` | ✗ | ✗ | ✗ | ✗ | 前者是主图的编辑产物，风格由参考图继承；后者是工程图，不是画面 |

**哪一类资产吃哪几层，由代码拥有**（`src/cinematography.mjs` 的 `ASSET_LAYERS`），
和 `isHuman()`、`FRAMING` 同一条规矩：结构性判断不能指望模型或使用者自觉。
契约只拥有"这几层说什么"。

### 资产复用同一张焦段表

一部戏的焦段语言只有一张表，资产不另起一套。肖像＝特写、身份图＝全景、场景主图＝远景。
这样"85mm 拍脸"在肖像和特写关键帧上是同一个数，不会自相矛盾。

### 按资产种类覆盖

```jsonc
{
  "assets": {
    "portrait": { "optics": { "lens_mm": 105, "depth_of_field": "极浅景深" } },
    "master":   { "lighting_setup": { "temperature": "冷调 5600K" } }
  }
}
```

结构和每镜覆盖一致，`optics.*` / `lighting_setup.*`。没写就走全片值。

## 每镜覆盖

导演稿里两个可选对象，写了就覆盖契约：

```jsonc
{
  "framing": "近景",
  "optics": { "lens_mm": 100, "depth_of_field": "极浅景深，只有眼睛清晰" },
  "lighting_setup": { "key_direction": "正前方柔光", "ratio": "高反差" },
  "lighting": "晨光穿过窗棂落在她半边脸上"
}
```

覆盖是**逐项**的：`lighting_setup` 只写了 `ratio`，其余仍继承契约，不是整块替换。

## 验收

摄影契约改了之后，必须用 dry-run 看真实提示词，不能只看代码：

```powershell
node cli/keyframes.mjs <项目/board.json> --direction <项目/render.plan.json> --dry-run
node cli/assets.mjs <项目/board.json> --dry-run --skip-gate
```

看三件事：风格头是不是在最前面、是不是逐字没被改写、镜头和光有没有混进不该有的默认值。

改完契约的后续动作（重跑范围、重批票、与每镜覆盖的取舍）以文首的警告块为准 —— 提示词变了，产物就是新的产物。
