# 导演与生成单元

生成、修改或评审导演方案时读取本文件，同时读取 `references/director/brief.md` 和 `references/director/schema.md`。具体结构由后两者拥有，本文件只说明流水线如何使用导演结果。

## 导演稿由谁写

来源、登记与票据规则见 [`workflow.md`](workflow.md) 的导演入口，**本文件不重复那份规则**。这里只写「由对话里的 Agent 直写」时，**交付前必须自己过一遍**的清单：

1. **先把契约读全**：`director/brief.md`（决策规则）+ `director/schema.md`（输出结构）。两者合起来就是 `cli/direct.mjs` 喂给模型的提示词 —— 直写时你替的就是那个模型，不是"随手写个 JSON"。
2. **单元边界按本文件的判据划**，不按叙事拍点数划；边界理由只能取 schema 允许的那几类硬理由。
3. **台词只能填行号**，原文由代码逐字搬运。任何一句台词文字出现在导演稿里都算失败。
4. **时间轴是单元内局部时间**：每个单元第一镜 `at = 0`，且 `at + duration_s ≤ 15`；不要用跨单元累计时间。
5. **交付前逐条对照 schema 的字段表** —— 必填项、枚举取值、`n`/`at` 连续、`emotion_analysis` 覆盖每个 on-screen 造型。**机器校验已经取消，没有人替你抓格式错**，要到编译阶段才暴露。
6. **别把"写完了"当成"通过"**：登记只留痕，direction 人工票仍由用户签。

## 单元不是机械剪辑点

生成单元表示视频模型一次连续表演的范围，不等于最终剪辑的一刀。

- 连续时空、角色集合稳定、动作关系简单时，可以在一次生成中包含多个内部镜头。
- 不因为模型支持 15 秒，就把每段都写成 15 秒。
- 不因为存在多个叙事拍点，就强制每拍生成一个视频。
- 边界必须有具体原因：场景变化、角色集合变化、状态锚点变化、动作风险过高或时长超过能力边界。

## 动作复杂度

以下属于高风险状态转换：

- 多角色身体接触。
- 抓取、递交、吞下、放下等交互。
- 主体进入、离开、出现或消失。
- 大幅位移或复杂运动轨迹。
- 形态、服装或物体状态变化。
- 明显空间重排或遮挡关系变化。

一个生成单元最多安排一个高风险状态转换。超过一个时：

1. 优先简化表演；或
2. 在稳定状态处设置 `state_transition_anchor`，拆成新的生成单元。

不能仅按“动作数量”切割。几个低风险表情和小动作可以连续完成；一个复杂抓取即使只是一句话，也可能需要独立单元。

## 时长

- 先保证完整对白和动作，再决定时长。
- 台词时长应由实测音频或保守语速估算反推。
- 单元过短而模型存在最短生成档位时，只增加执行预算，不改导演内容时长；后期裁回。
- 单元接近 15 秒上限时给出风险提示，但不因此自动拆分。
- 禁止按固定 5/10/15 秒网格机械切分。

## 关键帧起点

每个单元必须描述可稳定绘制的动作起点：

- 人物已经站好或坐好。
- 手尚未完成复杂接触。
- 需要出现的主体已经明确列入画面。
- 构图、景别、朝向和空间关系清楚。

不要把高速动作中间态、模糊接触瞬间或“正在变成”作为首帧。

### 一个单元里放多个主体：先看深度差

关键帧是**一张图**。让两个主体在**不同深度**同框（一个近景、一个在中景背景），同时又要竖屏全景、
又要"两个人都清楚可见、都不许裁脚"，这几条会互相打架 —— 模型只剩一个出路：**把远处那个也放大**。

实测（`bike_stare` 2026-09-19）：一个单元里让女生在近景小径上走、男生在中景背景骑车的**全景**关键帧，
出来是近景的女生正常大小、**背景的男生变成一颗巨大的头**（比例完全失调，自行车也没画出来）。
拆成两个单元（各拍一个人、各锚一张关键帧）后，两张都一次过。

**判据**：一个单元里要让多个主体同时可见时，先看它们的**深度差**。

- 深度差小（并排、同一条浅深度带）→ 可以放同一个单元、共享一张关键帧。
- 深度差大（近景 + 背景）→ **优先拆成两个单元**，各自一张关键帧；或者改调度，把两人放到同一条深度带。
- 拆开之后每个单元只有一个人，`identity_anchor` 就是开新单元的正当理由（见 `director/schema.md` 的六类硬理由）。

**但拆开不是唯一解 —— 更要紧的是选「模型天生会摆的组合」。** `pot_hit`（2026-09-20）在同一部片子里量到的成功率：

| 首帧里的主体状态 | 结果 |
|---|---|
| **一个人**（单人单元） | **5/5 一次过** |
| 两个人**隔着桌子对坐**（棋摊：模型每天都在画这类构图） | 一次过 |
| 两个人**一个站着、一个坐着**（要它造一个反直觉调度） | **1/5** —— 5 次里 4 次把它俩都按到椅子上；有一次还凭空抽出一台**监控摄像头** |

所以顺序是：**① 优先单人单元；② 需要双人时，选模型见过的自然配对（同桌、对坐、并肩）；③ 两者都不可行，才用上面的深度差判据拆单元。**
反直觉调度（一个站一个坐、一个在床上一个在地上）不要指望提示词压得住 —— 场景参考里只要有让人坐下的家具，它就会让人坐下。

### 意外要有来路，也要有悬念

`pot_hit`（2026-09-20）用户评审指出了两处硬伤，两条都值得当通用规则：

第一版是「她从楼道里走出来 → 头顶的花盆砸下来」，毛病有两个：

1. **触发源缺失** —— 花盆凭什么掉？没有原因，观众看到的只是"道具自己动了"。
2. **物理关系不成立** —— 她是朝镜头方向往外走的，而窗台在她**身后偏上**；成片里花盆看起来是**从她后面飞上来**砸她，用户一眼看出来了。

第二版按三条重做，成片里花盆是**从她正上方垂直落下**的：

- **先让角色走到落点正下方，再让危险落下。** 首帧必须把「他站在落点正下方 + 抬头往上看」写进 `keyframe_start`，让垂直关系**由首帧定死**，不要指望模型在运动里自己摆对。
- **给意外一个可见的触发源**（这里是猫踩翻花盆），而且**让观众比角色先知道**：触发那一拍要能独立成单元，排在"砸中"之前。
- **交叉剪辑的顺序**（用户给的、实测成立）：人物亮相 → 触发源出现 → 旁观者交代背景 → 人物走到险处 → 触发 → 落下砸中 → 旁观者反应 → 人物收尾。

**代价是单元数变多**（这一版 6 个单元、约 34 秒），但每个单元仍是单主体、`keyframe_cast ≤ 2`，反而比"一个单元塞多人"更稳：**6 段视频全部一次过、无返工**。

### 建立镜头与 0 秒首帧冲突时，不要为首帧牺牲叙事顺序

0 秒首帧**必须装下这一单元要锚定的角色**（否则它们没有身份参考，脸会飘），但**不要求角色在首帧里很大** —— 这是两件事，混起来就会出事。

**`no_chute`（2026-09-20）实测**：剧本的场次一是「一架螺旋桨飞机从画面右侧飞进来」（建立镜头），场次二才是机舱内的对话。导演为了让"两人背包差异"这个伏笔落在 0 秒首帧里（它的理由写得很清楚：「只有首帧会被身份图和后续所有单元反复锚定」），把 u1 排成了「**先两人特写 → 再拉远到整架飞机**」。结果成片**上来先说人、然后飞机才掠过**，与剧本正好相反，观众读到的顺序不连贯。

**判据**：

- **建立镜头永远排在前面，哪怕首帧里的角色很小。** 首帧用广角、角色在场（可以只是门洞里两个小点）；**身份锚定的责任交给下一个单元** —— 它的首帧本来就该是角色的近景或特写。
- **「硬切」落在单元边界上最干净。** 一个单元只要从"画面里没人"开始、后面才引入角色，那些角色在这一单元里就没有身份参考 → 会飘（`no_chute` 的飞机 + `pot_hit` 的花盆是同一个病的两种发作：**0 秒首帧的约束悄悄改写了叙事顺序或物理关系，而且不会报错**）。
- **例外（很重要）**：只要角色**在 0 秒首帧里在场**，哪怕很小，**单元内部的切镜是安全的** —— 首帧带进去的参考图会继续约束后面的近景。所以"广角飞机（人在门洞里）→ 切到舱内两人"这种一次单元内完成的开场是成立的；"纯空镜 → 切到人"则不行。

### 要模型守住的约束，必须写进镜头的 `action` / `emotion_analysis`

`end_state` 是**给下一个单元和连续性用的**：`cli/unit.mjs` 与 `src/h3-prompt.mjs` **都不读它**，视频模型看不到。而且**不该**把它塞进提示词 —— 那等于告诉模型"最后会变成这样"，它会提前把终态演出来。

**`no_chute`（2026-09-20）实测**：u1 的「门洞里两个身影仍在原处、**没有动作变化**」只写在 `end_state` 里，于是模型没有任何东西拦着它 —— 它看到"螺旋桨飞机 + 敞开的舱门 + 两个人"，自己演了一个跳伞：后四帧里女主角整个人悬在机身外的空中，而全片的跳伞要等到下一个单元。

**判据**：写完一个单元，把 `end_state` 单独念一遍，问「这里有没有哪个**不许发生**或**必须保持**？」—— 有，就把它搬进**该镜**的 `action` 或 `emotion_analysis.visible_behavior`，**正着写**（"脚步始终没有移动"），而不是留在 `end_state` 里等模型猜。

### 单元级返修

关键帧或视频暴露空间姿态、走位或动作不可执行时，导演负责重新思考该单元的调度；执行导演再把它编译成可绘制、可生成的硬约束。比如“仰面躺在床上”还必须明确身体沿床长边纵向、头靠枕头、躯干与床平行、重心完全在床垫上，以及镜头如何证明这些关系。场景师只负责床、房间、光线和机位环境，人物造型师只负责脸、发型、服装和妆发，不能替导演决定人物怎么躺或怎么移动。

返修只修改受影响单元的 `keyframe_start`、`end_state`、动作调度和必要的镜头字段；已确认剧本和无依赖单元保持不变。导演稿更新后必须重新校验、重新编译计划并重新取得导演确认，随后只重跑受影响单元及其连续承接链。

若导演语义已经正确，只是执行提示词遗漏了可绘制的几何约束，则不召回导演模型。由当前 Agent 写入项目级执行层覆盖（`reviews/keyframe-overrides.json`），例如把“仰面躺在床上”具体化为“沿床长边纵向、头靠枕头、身体完全在床垫上”；覆盖不得改变台词、剧情、角色设定或单元边界，且重跑后仍须人工确认。

## 台词所有权

成品剧本走逐行编译路线。代码负责搬运原文和行号，导演只决定：

- 哪个单元承载哪一行。
- 台词开始与结束的时间空间。
- 表演、景别、运镜和停顿。

校验必须确保每句台词恰好覆盖一次、顺序不变、文本逐字一致，并为说完整句话留出时间。

## 人工审阅重点

- 单元边界是否有真实生成理由。
- 是否存在为了凑 15 秒或为了切割而切割。
- 每段是否最多一个高风险状态转换。
- 台词能否在所给时长内完整说完。
- 角色切换前是否具备身份参考和稳定关键帧。
- 整体节奏是否服务故事，而不是服务模型参数。
