# 开工前清单

**新建项目，或开始新一轮生成之前读本文件。**

本文件只负责「开工前该按什么顺序检查什么」，**不复制规则原文**。
规则的所有者见 [`../SKILL.md`](../SKILL.md) 的「契约所有权」表；本文件遇到相关内容只给指针。

来源：`projects/beach_mosquito` 第一次完整走通后复盘（2026-09-17）。
该轮总花费约 3.3 元，**其中约 2.4 元花在返工上**。下面的检查项就是按"哪一条能省掉那些返工"排的。

---

## 一、先认清钱花在哪

**钱不花在生成上，花在返工上。**

| 阶段 | 单价 | 说明 |
|---|---|---|
| 导演 | 约 0.3 元/次 | 百炼文本接口，输入 12 元/百万 tokens、输出 36 元/百万 |
| 关键帧（百炼 `qwen-image-3.0-pro`） | 0.25 元/张 + 参考图 0.02 元/张 | 单张通常 0.29–0.31 元 |
| 关键帧（本地 ComfyUI） | **0** | 免费，但构图与服装锚明显弱一档 |
| 视频（本地 H3 `fast`） | **0** | 480×864，约 100 秒/条 |
| 视频（本地 H3 正式档） | **0** | 768×1344，约 5–6 分钟/条，见 [`video-h3.md`](video-h3.md) |

**推论：能免费试的必须先在本地试完，只把"成品"放到付费通道上。**
本地通道虽然画得差，但「方位词冲突」「否定词」「首帧锚定人数」这类**提示词缺陷它一样会暴露** ——
先用它把提示词缺陷筛掉，付费通道只用于出最终图。

## 二、环境体检（先查通路，别跑到一半才发现路是断的）

| # | 查什么 | 怎么查 | 失败的典型表现 |
|---|---|---|---|
| 1 | 本地 ComfyUI 是否 ready | `node cli/wait-ready.mjs` | 端口通 ≠ 模型已加载 |
| 2 | 本地 H3 单元契约通路 | 已有有效板子、计划和人工票时运行 `node cli/unit.mjs <项目/board.json> --direction <项目/render.plan.json> --unit <id> --dry-run`；新项目尚未过闸门时先查 `node cli/wait-ready.mjs`，不要伪造票 | 缺位置参数或来源/人工票时会明确拒绝；干跑只验契约和提示词，不验证实际 GPU 生成参数 |
| 3 | 百炼鉴权与配置 | `bl auth status`、`bl config show --output json` | 见下一条 |
| 4 | **百炼 CLI 是否会被 PowerShell 吃掉** | 见 [`troubleshooting.md`](troubleshooting.md) 的「CLI 通道调用失败」 | **静默无产出 / 等满超时** |
| 5 | 水印 | `bl config show` 里 `watermark` 必须为 `false` | 图上有水印，且会被当参考图传下去 |

**第 4 条最贵，是已复发的规则**（`🔁` 标注见 `troubleshooting.md`）：它不报错，只会静默失败，导演通道曾因此白等 10 分钟。
**导演通道已改为直连**，但**新增任何调用 `bl` 的通道，开工前确认它走 `runBailian` 这类直连方式，而不是经 `bl.ps1`。**

## 三、必须由用户确认才能进生成的项

这些**都是钱和画面的上游**，必须落进项目契约，不能由 Agent 猜。规则见 [`workflow.md`](workflow.md) 的「立项入口」。

1. **视觉风格**与**画幅**。
2. **已有参考资产**及其职责（身份硬参考 / 风格参考 / 灵感参考）；没有就记录为空。
3. **人物设定**。用户没给参考图时，**先给 2–3 版候选让用户挑，不要直接拍板**。
   人物的脸、体型、服装是整片画面的天花板，也是人物不一致时返工成本最高的一层。
4. **预计交付时长**。决定生成单元数，而单元数直接决定成片时长与生成成本。

## 四、开机前必做的三项提示词自检（**全部 0 成本，全部能省下付费返工**）

### 4.1 参考图配额

数一遍每个生成单元要传几张参考图：

| 通道 | 上限 | 常见分配 |
|---|---|---|
| 本地 Qwen-Image-Edit | 3 张 | 场景 1 + 人物 2 |
| 百炼 `qwen-image-3.0-pro` | 3 张 | 人物 2 + 场景 1 |

常规本地/百炼关键帧超过两名角色会明确拒绝；场景图保留在参考图列表中。连续性交接会先插入尾帧并限制总数，若原本已有场景加两名角色，最后一名角色参考可能被截掉；需要先简化构图或明确调整参考职责，再送审。

### 4.2 首帧锚定一致性（这条曾直接造成服装漂移）

`keyframe_cast` 决定**给谁传参考图**，`keyframe_start` 决定**画面里有谁**。两者必须一致。

- 首帧描述里出现了一个不在 `keyframe_cast` 里的人 → 模型会照文字把他画进来，
  而他没有参考图 → **衣服只能由模型自己编**（实测出过白背心、白裙、灰 T 恤）。
- 需要"两人同框"而配额不够锚两个人时：**重新设计这一帧的构图**，
  或者把第二个人改成"在画面之外"、用视线朝向画面外表达关系。

### 4.3 否定词与方位词

- **删掉所有"不要／禁止／别"句式**。规则与实测见 [`video-h3.md`](video-h3.md) 的「妆面污染」两轮记录：
  扩散模型对否定句的处理常等同于正向提示。
  `emotion_analysis[].avoid_symbols` 由 `src/director-execution.mjs` 转为正向表演边界，未知类别只供审阅，不原样拼进提示词；规则见 [`video-h3.md`](video-h3.md) 的对应小节。
- **左右方位只允许一种说法**。用「画面左侧/右侧」描述视线、同时又用「他的右肩」描述身体部位时，
  两者可能指向同一块区域而互相矛盾（实测：巴掌打对了肩，她的视线却看向了另一侧）。
  固定一种参照系，写完之后全篇统一。

### 4.4 台词时长

每个承载台词的单元，内容时长必须 ≥ 该句最低口播秒数。
秒数由 `src/orchestrate.mjs` 的 `estimateSpeechSeconds` 计算，不要目测。
导演方案校验器会拒收短于该值的镜头。

## 五、推荐顺序（一部长约 20 秒的竖屏短片）

```text
① 环境体检（第二节）                                   0 元
② 立项确认（第三节）                                   0 元
③ 剧本 → 用户确认                                      0 元
④ 导演：cli/direct.mjs + qwen3.8-max                   约 0.3 元
⑤ 资源：本地通道出图 → 用户确认                          0 元
⑥ 配额审计 + 提示词自检（第四节）                        0 元
⑦ 关键帧：本地试跑 → 提示词定稿 → 同一提示词上付费通道      0.3 元/张
⑧ 视频：本地 H3 逐段生成 + 逐段人工确认                   0 元
⑨ 合成 + 机器自检 + 终审                                0 元
```

按此顺序，一部长约 20 秒的短片合理花费约 **0.9–1.5 元**。

**最容易超支的三种做法**（都实际发生过）：

1. 关键帧提示词没自检就上付费通道，靠付费返工找缺陷。
2. 省掉导演那一步自己手写导演稿 —— 单元切碎会让视频端的"最低交付时长"重复支付，
   而且质量上限就是手写者的水平。
3. 在用户看到产物之前就替用户下"不行/通过"的结论，导致按错误前提规划重跑。

## 六、改工程时的两条硬约束

1. **改了 board 就要重跑 `compile-units`**（计划身份证绑 board 哈希），旧计划立即失效。
2. **不要手改 `render.plan.json`** —— `assertPlanProvenance` 会以「生成计划内容已被修改，项目身份证失效」拒绝执行，
   这是设计如此。要改内容就改导演稿再重编。
