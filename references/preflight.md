# 开工前清单

**新建项目，或开始新一轮生成之前读本文件。**

本文件只负责「开工前该按什么顺序检查什么」，**不复制规则原文**。
规则的所有者见 [`../SKILL.md`](../SKILL.md) 的「契约所有权」表；本文件遇到相关内容只给指针。

来源：`projects/beach_mosquito` 第一次完整走通后复盘（2026-09-17）。
该轮总花费约 3.3 元，**其中约 2.4 元花在返工上**。下面的检查项就是按"哪一条能省掉那些返工"排的。

---

## 一、先认清钱花在哪

**钱不花在生成上，花在返工上。**

| 阶段 | 单价 | 说明 |
|---|---|---|
| 导演 | 约 0.3 元/次 | 百炼文本接口，输入 12 元/百万 tokens、输出 36 元/百万 |
| 关键帧（百炼 `qwen-image-3.0-pro`） | 0.25 元/张 + 参考图 0.02 元/张 | 单张通常 0.29–0.31 元 |
| 关键帧（本地 ComfyUI） | **0** | 免费，但构图与服装锚明显弱一档 |
| 视频（本地 H3 `fast`） | **0** | 480×864，约 100 秒/条 |
| 视频（本地 H3 正式档） | **0** | 768×1344，约 5–6 分钟/条，见 [`video-h3.md`](video-h3.md) |

**推论：能免费试的必须先在本地试完，只把"成品"放到付费通道上。**
本地通道虽然画得差，但「方位词冲突」「否定词」「首帧锚定人数」这类**提示词缺陷它一样会暴露** ——
先用它把提示词缺陷筛掉，付费通道只用于出最终图。

## 二、环境体检（先查通路，别跑到一半才发现路是断的）

| # | 查什么 | 怎么查 | 失败的典型表现 |
|---|---|---|---|
| 1 | 本地 ComfyUI 是否 ready | `node cli/wait-ready.mjs` | 端口通 ≠ 模型已加载 |
| 2 | 本地 H3 单元契约通路 | 已有有效板子、计划和人工票时运行 `node cli/unit.mjs <项目/board.json> --direction <项目/render.plan.json> --unit <id> --dry-run`；新项目尚未过闸门时先查 `node cli/wait-ready.mjs`，不要伪造票 | 缺位置参数或来源/人工票时会明确拒绝；干跑只验契约和提示词，不验证实际 GPU 生成参数 |
| 3 | 百炼鉴权与配置 | `bl auth status`、`bl config show --output json` | 见下一条 |
| 4 | **百炼 CLI 是否会被 PowerShell 吃掉** | 见 [`troubleshooting.md`](troubleshooting.md) 的「CLI 通道调用失败」 | **静默无产出 / 等满超时** |
| 5 | 水印 | `bl config show` 里 `watermark` 必须为 `false` | 图上有水印，且会被当参考图传下去 |

**第 4 条最贵，是已复发的规则**（`🔁` 标注见 `troubleshooting.md`）：它不报错，只会静默失败，导演通道曾因此白等 10 分钟。
**导演通道已改为直连**，但**新增任何调用 `bl` 的通道，开工前确认它走 `runBailian` 这类直连方式，而不是经 `bl.ps1`。**

## 三、必须由用户确认才能进生成的项

这些**都是钱和画面的上游**，必须落进项目契约，不能由 Agent 猜。规则见 [`workflow.md`](workflow.md) 的「立项入口」。

1. **视觉风格**与**画幅**。
2. **摄影语言**：焦段、景深、机位高度、主光方向与光质、色温，以及要排除的风格。
   它决定「用什么机器拍」，与美术风格是两件事，**不能混为一谈**。规则与字段见 [`cinematography.md`](cinematography.md)；契约里没写的字段一个字都不进提示词。
3. **已有参考资产**及其职责（身份硬参考 / 风格参考 / 灵感参考）；没有就记录为空。
4. **人物设定**。用户没给参考图时，**先给 2–3 版候选让用户挑，不要直接拍板**。
   人物的脸、体型、服装是整片画面的天花板，也是人物不一致时返工成本最高的一层。
5. **预计交付时长**。决定生成单元数，而单元数直接决定成片时长与生成成本。
6. **每个角色的 `species`**（非人类卡司尤其）—— 开机前必查项。缺省不是"未知"，而是 `human`。
   🔁 **已复发（第 2 次记录，最近：`mimi_bone` 2026-09-19）**：立项 Brief 漏填 `species`，一条柴犬的肖像与身份图被注入人类条款。
   规则原文与完整说明的唯一所有者见 [`../schema/storyboard.schema.json`](../schema/storyboard.schema.json) 的 `characters[].species`（本文件不复制规则原文）。

## 四、开机前必做的提示词自检（**全部 0 成本，全部能省下付费返工**）

### 4.1 参考图配额

数一遍每个生成单元要传几张参考图：

| 通道 | 上限 | 常见分配 |
|---|---|---|
| 本地 Qwen-Image-Edit | 3 张 | 场景 1 + 人物 2 |
| 百炼 `qwen-image-3.0-pro` | 3 张 | 人物 2 + 场景 1 |

常规本地/百炼关键帧超过两名角色会明确拒绝；场景图保留在参考图列表中。连续性交接会先插入尾帧并限制总数，若原本已有场景加两名角色，最后一名角色参考可能被截掉；需要先简化构图或明确调整参考职责，再送审。

### 4.2 首帧锚定一致性（这条曾直接造成服装漂移）

`keyframe_cast` 决定**给谁传参考图**，`keyframe_start` 决定**画面里有谁**。两者必须一致。

- 首帧描述里出现了一个不在 `keyframe_cast` 里的人 → 模型会照文字把他画进来，
  而他没有参考图 → **衣服只能由模型自己编**（实测出过白背心、白裙、灰 T 恤）。
- 需要"两人同框"而配额不够锚两个人时：**重新设计这一帧的构图**，
  或者把第二个人改成"在画面之外"、用视线朝向画面外表达关系。

### 4.3 否定词与方位词

- **删掉所有"不要／禁止／别"句式**。规则与实测见 [`video-h3.md`](video-h3.md) 的「妆面污染」两轮记录：
  扩散模型对否定句的处理常等同于正向提示。
  `emotion_analysis[].avoid_symbols` 由 `src/director-execution.mjs` 转为正向表演边界，未知类别只供审阅，不原样拼进提示词；规则见 [`video-h3.md`](video-h3.md) 的对应小节。
- **左右方位只允许一种说法**。用「画面左侧/右侧」描述视线、同时又用「他的右肩」描述身体部位时，
  两者可能指向同一块区域而互相矛盾（实测：巴掌打对了肩，她的视线却看向了另一侧）。
  固定一种参照系，写完之后全篇统一。
- **不要在提示词里写"光源在哪"** —— 那会把光源本身画进画面。实测（`bike_stare` 2026-09-19，场景主图）：
  写「太阳高悬在画面正上方偏前的位置」→ 得到一张**太阳入镜 + 一道竖向镜头眩光**的主图；
  改成只描述**它造成了什么**（「日光充足明亮，物体在正下方投出短而硬的暗影；天空是均匀的高亮浅蓝色」）→
  光源退出画面，"正午顶光"的意图照样成立。**要什么光就写它的后果，不要写它的位置。**

### 4.5 非人类卡司：执行层的人类约束必须先摘掉

卡司里只要有 `characters[].species ≠ human` 的角色，**先读 [`draw-specialist.md`](draw-specialist.md) 的「非人类卡司」那一节**：
执行层的景别、承托关系、镜头排除项、参考图职责四处措辞都是按「人类 + 床铺」写的，会原样进关键帧提示词。

> 🔁 已复发（最近：`bike_stare` 2026-09-19；机器计数至少跨 2 个剧目、3 次关键帧生成）。
> 规则、代码位置与完整清单见 [`draw-specialist.md`](draw-specialist.md)（本文件不复制规则原文）。

### 4.4 台词时长

每个承载台词的单元，内容时长必须 ≥ 该句最低口播秒数。
秒数由 `src/orchestrate.mjs` 的 `estimateSpeechSeconds` 计算，不要目测。
短于该值的镜头在人工审阅时会被打回（机器不再自动拒收，但这条约束没变）。

## 五、推荐顺序（一部长约 20 秒的竖屏短片）

```text
① 环境体检（第二节）                                   0 元
② 立项确认（第三节）                                   0 元
③ 剧本（当前对话 Agent 直写 → register-agent）→ 用户确认    0 元
④ 导演稿（当前对话 Agent 直写 → register-direction）→ 用户确认  0 元
   （只有显式调 `cli/script.mjs generate` / `cli/direct.mjs` 才产生模型费用）
⑤ 资源：本地通道出图 → 用户确认                          0 元
⑥ 配额审计 + 提示词自检（第四节）                        0 元
⑦ 关键帧：本地试跑 → 提示词定稿 → 同一提示词上付费通道      0.3 元/张
⑧ 视频：本地 H3 逐段生成 + 逐段人工确认                   0 元
⑨ 合成 + 机器自检 + 终审                                0 元
```

按此顺序，一部长约 20 秒的短片合理花费约 **0.9–1.5 元**。

**最容易超支的三种做法**（都实际发生过）：

1. 关键帧提示词没自检就上付费通道，靠付费返工找缺陷。
2. **跳过导演这一步** —— 代价从来不是"手写"本身，而是两件事：**单元切碎**会让视频端重复支付"最低交付时长"，**不按契约交付**（[`director/brief.md`](director/brief.md) + [`director/schema.md`](director/schema.md)）会让下游编译不出来。
   Agent 按契约直写导演稿是**合法来源**（见 [`workflow.md`](workflow.md) 的导演入口，票据记 `agent_draft`），纯本地跑时它是唯一来源；但与调模型相比，**质量上限就是执行 Agent 自己的水平**，这一点在 direction 闸门只能靠人判断，不能靠"过程合规"抵消。
3. 在用户看到产物之前就替用户下"不行/通过"的结论，导致按错误前提规划重跑。

## 六、改工程时的两条硬约束

1. **改了 board 就要重跑 `compile-units`** —— 不是因为会被拦，而是因为计划身份证记录着这份计划从哪份 board / story / 导演稿编译而来；不重编，这份计划的来源记录就是错的。
2. **不要手改 `render.plan.json`** —— 计划身份证**只作留痕，不作闸门**（`assertPlanProvenance` 已随「去掉机器审核」移除，手改不会被代码拦住）。要改内容就改导演稿再重编；越过它没人拦你，代价是这份计划再也说不清是从哪来的。
3. **改了 `cinematography.json` 就要重跑受影响产物、重批票** —— 契约是关键帧 / 视频提示词的输入，但票绑的是产物哈希、不绑契约；不重跑，旧票照样全绿、`ready-assemble` 照常放行，缝出两部戏到终审才暴露。只想改一镜的光 / 焦段？用 `shot.optics` / `shot.lighting_setup` 每镜覆盖，别动契约（规则正本见 [`cinematography.md`](cinematography.md) 文首警告块）。
