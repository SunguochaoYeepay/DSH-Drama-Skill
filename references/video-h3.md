# H3 视频生成

运行 FastH3/H3、决定视频规格或编写视频提示词时读取本文件。

## 当前模型策略

H3 暂时不可替换。视频成本高，因此先验证导演节奏、关键帧和动作可行性，再进行正式规格生成。

| 用途 | 规格 |
|---|---|
| 默认规格 | `fast` → FastVideo FastH3 8 步 + VSA，`i2v` 单首帧；`AIH_VIDEO_NORMAL_SIZE=480x864` |
| 首尾帧 | `fast` + `--last-keyframe` → FastVideo FastH3 `fl2v`；使用本次指定的尺寸 |
| 高质量 | `fast` + `--quality high` → FastVideo FastH3 `i2v`/`fl2v`；`AIH_VIDEO_HIGH_SIZE=768x1344` |
| 显式多参考实验 | `--profile draft|balanced|final` → 基础 H3 `r2v`；不是正式档默认值 |

**送审与确认规则见 [`workflow.md`](workflow.md) 的「视频规格与重抽」**。本文件只负责规格。

`fast` 档支持两种输入：只有首帧时走 `i2v`；同时传入 `--last-keyframe` 时走 `fl2v`。
FastH3 不支持多图 Ref2VA。首帧/尾帧应当由已确认的关键帧承担身份、构图和状态锚定；只有明确需要多参考实验时，才选基础 H3 的 `r2v` profile。

`i2v`/`fl2v` 与 `r2v` 的提示词结构不同。FastH3 主要依靠首尾关键帧和镜内可观察动作；
`r2v` 才使用多图 `subject_definitions` / `retention_analysis`。因此常规尺寸（默认 `480x864`）可以判断节奏、动作、对白和明显漂移，
但不能替代 `768x1344` 下的纹理、文字、微小配饰等细节验收。

`--profile` 决定模型路线，`--quality` 决定尺寸，两者正交。`--quality high` 使用 `.env` 的高质量尺寸；不会自动切换到耗时更长的基础 H3 `r2v`。

注意力由根目录 `.env` 的 `AIH_VIDEO_ATTENTION=vsa` 决定，`cli/unit.mjs` 显式传给本地 `gen.py`。默认保留 FastH3 8 步模型并接 VSA。Sage 与 VSA 不叠加；单次实验可用 `--attention sage` 覆盖，不改变项目默认值。同图、同种子、5.17 秒实测热态 VSA 37.0 秒、Sage 38.2 秒，差异很小，但输出动作不同。


**算力近似正比于「像素 × 步数」**（2026-09-17 实测，RTX 4090，243 帧）：

| 配置 | 相对算力 | 实测耗时 |
|---|---|---|
| `480x864` + `draft`（4 步） | 1.0× | 未测 |
| `480x864` + `balanced`（8 步） | 2.0× | 未测 |
| `768x1344` + `draft`（4 步） | 2.5× | 未测 |
| `768x1344` + `balanced`（8 步，基础 H3 实验） | 5.0× | 5.6–7.2 分钟/条（单次项目记录，仅供估算） |

低分辨率**不能**用来验收小尺寸细节：纹身这类只有十来像素的目标在 480 宽下会退化成黑点，
预览只能看构图、身份、动作节奏。

具体可用 profile 和工作流节点由 `comfy-studio` 及 `cli/unit.mjs` 实现。不要在 Skill 中重新写死会随安装变化的节点路径。

## 时长和帧数

- 15 秒是单次能力上限，不是默认目标。
- 内容时长来自台词和动作；生成时长可以向模型合法帧数档位上取整。
- H3 帧数必须落在 `17k+5` 网格上，由代码计算，不能人工随意取整。
- 生成结果按导演内容时长裁回，不能通过砍尾巴解决超长，否则会截断台词。
- 正式分辨率下的长视频显存风险更高；不要把低分辨率可跑的最长时长直接套到正式规格。

## 单元策略

- 同一连续时空可在一段视频内使用多镜提示词。
- 单元边界由导演的动作复杂度分析决定，执行层不得再次机械拆分导演单元。
- 关键帧是第一张参考图。
- 非 FastH3 参考视频模式可继续传人物和道具资产，以约束身份。
- FastH3 有单首帧 `i2v` 和单首尾帧 `fl2v`；不要假设它具有基础 H3 Ref2VA 的多图参考能力。

## 提示词

使用工具生成的官方字段结构，不临时改成散文提示词。提示词需要覆盖：

- 参考图职责或首帧对齐。
- 每个内部镜头的切点、景别、主体、动作、机位和光线。
- 人物外观锚点。
- 原文台词及说话人。
- 环境声和声音要求。

**官方一手源（写或改提示词前可核对）**：MiniMax-AI/MiniMax-H3 仓库自带
`skills/h3-prompt-writing/references/base-en.txt`（T2VA/I2VA/FL2VA/L2VA 三段结构）与
`ref-en.txt`（full-reference 六段结构）。我们此前只靠二手与自撞，此后以这两份为准绳；
下文规则均已对照原典校准过一遍（2026-09-21）。

### 说话人与对白（官方语法 + 外部实证）

1. **说话人稳定 ID**：`(S1)`、`(S2)`；多人同说用 `(S1,S2)`；跨镜保持同一 ID；
   **从不发声的角色不分配 ID**。首次出现时在 `<d>` 外交代画内/画外与音色
   （年龄、性别、高低、语速）——身份信息、ID、动作都在 `<d>` 外，`<d>` 内只有
   语言标签 `[Chinese]` 和逐字台词。台词跟在该说话人的可见动作句后面，不集中堆在文末。
2. **画外音**必须用固定短语 `says in an off-screen voiceover`，并且每个画外音 `<d>` 块
   之后立即声明对应画面内角色 `while his lips remain completely closed`。
3. **口型会落在画面里最显眼的正脸上**（外部实证：drama-skills 3 次实测，远处小孩喊话、
   近处骑手正对镜头时，口型 2 次落在不说话的骑手脸上；补两条写法后 3/3 全对）：
   - 首选**调度解决**——让不说话的人在台词期间出画或背身；
   - 躲不开时**明写不说话者嘴唇完全闭合**（同官方画外音句式）；
   - 出片后仍要人工核对口型落在谁脸上。
4. **对白容量**：H3 中文小样本实测约 **4.1 个可发声字/秒**，且出现过赶词与静默截断。
   剧本预算按 4 字/秒做（`story-craft.md` 的台词工艺同此口径）；镜长够但开口太晚一样赶词，
   开口时机也要算。
5. 同一句台词跨切镜用 `<scenetrans>`（连接点两侧都写，声明声音跨切镜继续）；
   视频结尾有意截断用 `<cutoff>`（只用于剧本要求的截断，不用于装不下的台词）。
6. 切镜时间戳官方格式是 `[Shot 2] At 00:03.500, ...`（MM:SS.mmm）；`[Shot 1]` 不带时间戳。
   我们当前代码输出 `At 03.50 seconds` 格式，偏差见文末「代码层偏差清单」。

### 声音三字段

- `integrated_multimodal_description`（或 r2v 的 `detailed_description`）：对白、唱歌、
  画内音乐等剧情同步声，跟画面一起写进时间线。
- `overall_soundscape`：1–4 句连续段落，只写环境声、物理音效、非语言人声；对白不在
  这里重复。全片静音才写 `N/A`。写音效按**三层**组织（吸收自 action-fight-prompt 的
  音效分层，2026-09-21）：**力量层**（发力来源的声音——蹬地闷响、布料摩擦、吐气）、
  **材质层**（接触物材质——金属锐鸣、木裂、甲面钝响）、**生物层**（人的非语言声——
  咬牙、闷哼、粗重呼吸）。动作戏尤其要三层都有：只有"打斗音效"这种统称，模型给不出
  打击感；三层词库与打击感写法的剧本侧工艺见 `story-craft/action.md`。
- `non_diegetic_music`：观众可听、角色听不到的配乐，写乐器/速度/动态，不写抽象情绪词；
  **没有就显式写 `N/A`，不要留空**——留空出现过模型自己补配乐（外部实证）。

### r2v / full-reference 六段（实验路径，官方语义）

`subject_definitions → summary → retention_analysis → detailed_description →
overall_soundscape → non_diegetic_music`，全部一段提示词一次提交。官方语义要点：

- **`<Subject N>` vs `<Picture N>` 分工**：`<Picture N>` 只用于帧/构图锚点（首帧、尾帧、
  storyboard）；**身份、造型、场景、风格参考图应折进 `<Subject N>` 的定义行**
  （`<Subject 1> is the woman in <Picture 2>, with ...`），不单独占 Picture 编号。
  `<Video N>` 只表达整片关系（编辑/续接/节奏结构）；复用其中可见内容仍归 `<Subject N>`。
- **`summary` 必须以任务类型前缀开头**：`[reference generation]`、`[keyframe completion]`、
  `[video continuation + audio reuse]` 等，组合用 ` + ` 连接；不引入新标签。
- **`retention_analysis` 逐标签一行**，用固定保留强度词汇：可见内容
  `fully_preserved / partially_preserved / attribute_transfer / weak_reference`；
  音频 `fully_copy / partially_copy / reference / weak_reference`。不在此节写 `(Sx)`。
- **`<Audio N>` 与说话人**：参考音色写 `<Audio 1> is the voice-timbre reference for
  <Subject 3> (S1)`——`(Sx)` 复用全局说话人顺序，不在音频定义里独立编号；
  只引用音色时**不把参考音频里的原话带进目标视频**。
- **标签编号即挂图顺序契约**：`<Picture N>` 的编号必须与实际挂图顺序一致——两套编号
  不一致时接口不报错，模型收到的是互相矛盾的素材说明（外部实证强调过这一点）。
- 素材上限（官方 API）：1 首帧 + 1 尾帧 + 9 张 reference_image + 3 段 reference_video +
  3 段 reference_audio；首尾帧与多图参考**互斥**。连续段喂上一段实际视频时，上一段视频走
  `reference_video`、其尾帧走 `reference_image`，不把尾帧标成 first_frame。

> ⚠ **通道注意**：以上 full-reference 语义面向官方 API。我们默认走本地 FastH3 `i2v`/`fl2v`
> （无多图 Ref2VA），只有 `r2v` 实验 profile 才消费六段结构；本地实现是否完全遵守官方
> 方言语义未逐一验证，标注"实验路径"就在这里。

用可观察的外观和动作描述情绪。避免“脸颊越来越红”“羞得满脸通红”等容易被模型画成妆容变化的演绎词。
（2026-09-17 实测：`脸颊涨红`/`脸颊泛红` 会让末镜长出两块腮红 + 亮红唇，而 retention 里的 `never render it as blush` 压不住它。）

这条靠代码兜底，不靠人记得：`src/h3-prompt.mjs` 的 `DEACT` 词表会把这类词换成不带颜色词的生理表演。
凡是**逐字进入提示词**的表演文字都必须在词表的作用范围内 —— 目前是 `shot.action`、`summary`、
以及 `compileDirectorExecution()` 产出的 `visible_behavior` 三处；新增任何一条进提示词的文字通路时，
记得把它也接上 `DEACT`，否则就是漏的。

### 妆面污染：两次实测记录（都是阴性）

症状：女性角色「震惊/恼怒」特写长出两块腮红 + 亮红唇，与素颜设定冲突。

| # | 单变量改动 | 结果 |
|---|---|---|
| 1 | 把 `脸颊涨红`/`脸颊泛红` 全部换成 `脸颊绷紧`（提示词内三处，见上） | **无效**，腮红照旧 |
| 2 | 把 retention 里那句 `a faint real flush on the cheeks is allowed, but never render it as blush, rouge, lipstick or any other makeup, and never darken or redden the lips` 换成纯正向复现约束 | **有效**，腮红与亮红唇消失 |

教训 1 的推论：**「把描述里的红字删掉」不足以消除妆面** —— 模型对「女性情绪特写」的先验很强。

教训 2 的结论（已验证）：那句否定式约束把 `flush / blush / rouge / lipstick / redden` 串在同一句里，
**本意是否定，实际等于给模型递了一份「妆」的词表**；扩散模型对否定句的处理常等同于正向提示。
现该段整段不含任何妆/色词汇，只保留「与参考图完全一致，不加不减」。
三版末帧对照存 `projects/mosquito_tattoo/reviews/g001_face_zoom_3way.png`。

**因此：写 H3 提示词时，不要用「不要画 X」的句式去抑制某个视觉元素，尤其当 X 本身是名词。
改用「与参考图完全一致」这类纯正向的复现约束，并把该元素从整段文字里彻底拿掉。**

### `avoid_symbols` 的执行边界

**同一根因的另一个出口**：`emotion_analysis[].avoid_symbols` 是导演的**分析字段**（"这个角色此刻最容易被读成什么相反情绪"），
校验器要求它存在且非空。但执行器曾把它自动拼成「；禁止表现为：微笑、崇拜眼神、卖萌歪头」并紧跟「视线：…」之后 ——
**等于把「微笑」这个词直接递给了模型**。

实测（beach_mosquito 2026-09-17）：h3 提示词里带这段时，视频里女主挨了一巴掌之后的反应**笑了**；
把该段从提示词拿掉（`avoid_symbols` 仍保留在导演稿里、仍通过校验）后重跑，「笑了」消失。

**处置**：`src/director-execution.mjs` 不再原样拼接 `avoid_symbols`。已知类别会被编译成不包含负例词的
正向表演边界；未知类别保留在导演稿中，作为人工审阅目标，不直接进入生成提示词。

**推论**：不要把负例词表直接交给生成模型。能确定性改写的，转换成正向可观察边界；不能安全改写的，
留给 QA 和人工审阅，不能假装已经由提示词解决。

## 字幕与声音

H3 可能把对白烧成画面文字，提示词通常压不住。先保留原视频供审阅，最终通过 `cli/desub.mjs` 做后期过滤，不要为了隐藏字幕删除对白提示。

默认使用 H3 联合生成的原生人声与环境声。不要无条件叠加同一句 TTS，否则会出现双重人声。TTS 可以用于时长估算，只有在明确决定替换声音时才进入最终混音。

### 合成音床与响度（外部实证预警；响度统一已于 2026-09-21 落地）

每段 H3 生成自带独立音床（环境声、音效），`assemble-units` 逐段转码后 concat，
**接缝处环境声不连续是构造性风险**，不是偶发 bug。外部工程实跑教训（drama-skills RUN-LOG，
他们真剪过片才写下来的）：

1. 逐段各自烧音床 → 剪辑点声音跳变/断层；含台词单元我们保留完整生成时长，接缝更多。
2. **单遍 loudnorm 不可信**：实测单遍响度归一偏离目标 3.7 dB。~~我们完全没有做任何响度
   统一~~ **已修（2026-09-21）**：`assemble-units` 对每段做**两遍式 loudnorm**（第一遍测量、
   第二遍 linear 应用，默认 -16 LUFS / TP -2 / LRA 11，可用 `AIH_ASSEMBLE_LUFS` 等环境变量
   覆盖）；测量解析失败（如纯静音段打出 -inf）时退回单遍动态模式；无音轨段自动跳过。
   行为测试：两段原始响度差 24 LU 的素材归一后段间差 ≤3 LU。
3. 转写字幕不能当字幕用（时间轴与说话人不可靠）。
4. 可用时长可能短于声明时长——生成后要实测每段真实时长再排剪辑点。

环境声的**内容**不连续（鸟叫换成车流）响度统一管不了，终审时**必须戴耳机听接缝**
（见 `qa-and-review.md` 的终审清单）。

## 逐段执行

每次只生成一个单元：

1. 确认整组关键帧票据有效。
2. 若不是第一段，确认上一段人工票据有效。
3. 生成本段。
4. 自动做技术检查和抽帧。
5. 展示完整视频和总览，等待人工确认。
6. 用户确认后才生成下一段。

禁止同时运行多个 H3 视频任务。并发会争抢显存，也会绕过前一段对后一段的反馈。
