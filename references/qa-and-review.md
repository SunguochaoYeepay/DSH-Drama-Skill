# QA、人工审阅与合成

检查阶段产物、向用户送审、准备合成或终审时读取本文件。

## 原则

机器 QA 回答“文件是否具备送审条件”，人工回答“内容是否可接受”。两者不能互相替代。

不要因为自动评分高就代签人工票，也不要因为肉眼看起来正常而跳过解码和音轨检查。

## 图片送审

提供：

- 带编号的整组总览。
- 每张原图或可直接打开的本地文件。
- 机器 QA 的失败项和警告。
- 对应的镜头/单元设计描述。

缩略图只用于比较，判断服装、五官、文字和细节时必须看原图。

## 视频送审

每段生成后运行 `cli/inspect.mjs`，至少检查：

- 视频可完整解码且无错误。
- 分辨率、画幅、帧率和时长。
- 音轨存在；有对白的段落不能近似静音。
- 首帧、末帧和均匀抽取的八帧总览。

向用户同时展示完整视频与抽帧总览，人工检查：

- 人物身份、发型、服装和体型是否漂移。
- 动作是否飞掉、穿模、融合或突然消失。
- 台词是否完整、清楚、由正确角色说出。
- 切镜和节奏是否自然。
- 是否出现错误文字或字幕污染。
- 结尾是否形成可接受的剪辑点。

人工确认绑定视频本身，不绑定抽帧图；抽帧图可以重新生成而不使内容票失效。

## 合成前

运行：

```powershell
node cli/review-gate.mjs ready-assemble --project <项目目录> --plan <render.plan.json>
```

只有计划中的每个单元都存在有效人工票据时才能合成。不得用“整体看起来差不多”代替缺失的逐段票。

合成前根据项目决定是否运行 `cli/desub.mjs` 过滤 H3 烧入字幕。必须保留原始片段，后处理产物使用新路径。

## 成片机器检查

- 完整解码一遍，错误行为零。
- 视频时长与各段裁切后的时间线一致。
- 音频编码参数统一、音轨可解码、总体非静音。
- 检查全黑、全白、冻结帧和明显接缝。
- 音频响度适合手机播放，避免削波。

“文件存在”和播放器能显示时长都不算检查通过。

## 最终人工审阅

展示完整成片并要求用户重点看：

- 故事是否完整，笑点或高潮是否成立。
- 台词是否完整，声音是否自然。
- 人物和空间连续性。
- 视频段接缝、字幕过滤区域和画面裁切。
- 开头是否快速进入内容，结尾是否完整。

用户明确确认后才能记录 `final` 票据。机器检查不得自动写票。
