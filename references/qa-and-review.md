# 人工审阅与合成

向用户送审、准备合成或终审时读取本文件。

## 原则

**没有机器审核这一步。** 产物生成后直接送审，能不能用由人判断。
工程不提供视觉模型打分、成片自检，也不对契约或来源票做强制校验。

唯一的自动化是**人工票据本身**：`review.approvals.json` 记录"人看过并认可"的产物哈希。
产物被替换后旧票自动失效 —— 这是防止「确认了 A、交付了 B」，不是替人判断质量。

## 图片送审

提供：

- 带编号的整组总览。
- 每张原图或可直接打开的本地文件。
- 对应的镜头/单元设计描述。

缩略图只用于比较，判断服装、五官、文字和细节时必须看原图。

### 签字前先跑一次空间核查

只要这一镜涉及**两人以上同框、对谈、机位换边**，或者**没有落幅**，签字前先跑：

```bash
node cli/check-subjects.mjs <项目目录>     # 画里有没有人、几个人（检出没人 → 退出码 1）
node cli/space-check.mjs  <项目目录>     # 生成 reviews/space-check.md：声明 → 自动结论 → 待人工确认
```

它**不判**"两人是否相向、桌子在不在中间"（那类只能人眼看，机器会给出自信的错答案），
它判的是**纯逻辑能判的**：人数、轴的视线方向、逐内部镜头的视线一致性。
**声明写在哪、取值怎么填、机器与人各判什么 → 见 [`space-check.md`](./space-check.md)。**

## 视频送审

需要抽帧或核对规格时可用 `cli/inspect.mjs`（它是给人看的工具，不是审核）：

```powershell
node cli/inspect.mjs <媒体文件> --aspect 9:16 --first-last
```

向用户同时展示完整视频与抽帧总览，人工检查：

- 人物身份、发型、服装和体型是否漂移。
- 动作是否飞掉、穿模、融合或突然消失。
- 台词是否完整、清楚、由正确角色说出。
- 切镜和节奏是否自然。
- 是否出现错误文字或字幕污染。
- 结尾是否形成可接受的剪辑点。

人工确认绑定视频本身，不绑定抽帧图；抽帧图可以重新生成而不使内容票失效。

## 合成前

运行：

```powershell
node cli/review-gate.mjs ready-assemble --project <项目目录> --plan <render.plan.json>
```

只有计划中的每个单元都存在有效人工票据时才能合成。不得用"整体看起来差不多"代替缺失的逐段票。

合成前根据项目决定是否运行 `cli/desub.mjs` 过滤 H3 烧入字幕。必须保留原始片段，后处理产物使用新路径。

**去字幕换了产物，就必须重批该段的 `clip` 票。** 票绑的是产物哈希，新路径上那张票不存在 —— 不重批，`assemble-units` 取到的仍是原片（带硬字幕），去字幕白做。重批方式：`node cli/review-gate.mjs approve --project <项目目录> --stage clip --id <单元 id> --artifacts <去字幕后的片段>`。

## 最终人工审阅

展示完整成片并要求用户重点看：

- 故事是否完整，笑点或高潮是否成立。
- 台词是否完整，声音是否自然。
- 人物和空间连续性。
- 视频段接缝、字幕过滤区域和画面裁切。
- **接缝的声音**：每段 H3 自带独立音床，直接 concat 的接缝处环境声不连续是构造性风险
  （见 `video-h3.md`「合成音床与响度」）；目前合成无响度统一，段间响度差会原样进成片。
  **必须戴耳机逐个接缝听**，不能只看画面。
- 开头是否快速进入内容，结尾是否完整。

用户明确确认后才能记录 `final` 票据。代码不得自动写票。
